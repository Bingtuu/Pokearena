## 完成总结（DONE 时填写）

- **PRD v1.7**：FR-3.4 展开为逐条形式化计数语义——①deck_size=60；
  ②name_limit 双层判定（单 card_id ≤ deck_limit；同名组 ≤ 组上限，组内含
  V-UNION 部件 = 4 否则 max(成员 deck_limit)；**基本能量豁免**——官方规则
  基本能量不受 4 张限制，本次设计补入）；③ace_spec_limit 全卡组 ≤1；
  ④radiant_limit 全卡组 ≤1。FR-8 Violation 语义全集定稿：kind 新增
  `unknown_card` / `radiant_limit`（additive）；**evolution_chain 定死为
  预留类型**——官方卡组构筑规则无进化链完整性要求，当前规则集不产生，
  保留枚举供未来赛制启用。DeckReport 字段定稿（ok/deck_size/format/date/
  snapshot_id/violations，Violation 增 `count`）。
- **实现**：`ptcgdb/legal/deck.py` 纯函数核 `check_counts(deck, cards_by_id,
  groups_of) -> list[Violation]`；`Violation` frozen schema 落
  `ptcgdb/schemas/models.py`。单卡上限仅在 < 组上限时单独报告（V-UNION 部件
  场景），普通卡由组违规覆盖，避免同一事实重复报告。
- **测试**：13 用例全绿——合法 60 张、59/61、unknown_card、同名 5 张、
  博士的研究跨插画归组（3+2>4）、owner 前缀不同名、ex 后缀不同名、
  ACE SPEC 跨卡名/同卡双违规、光辉全局、◇ 同名限但无全局、V-UNION 部件、
  基本能量豁免。真实库冒烟：60 张合法卡组零违规；违规构造（同名 5 + 2 种
  ACE + 2 种光辉）精确命中三类。194 测试全绿、ruff 通过。
- **边界**：banned / not_legal 判定属 validate_deck（task 026）组合
  select_snapshot/build_pool 后的职责，不在本模块。
