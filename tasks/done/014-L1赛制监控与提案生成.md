## 目标
对官网三个页面做正文提取 + hash 快照比对，变更检测后自动生成与 `legal-apply` 兼容的结构化提案 `proposals/YYYYMMDD_*.yaml`；解析不确定的变更标记"需人工处理"，不做猜测性自动 apply。

## 侦察结论（2026-08-01，各 1 次请求）
- 站点为 WordPress。三页正文容器均为 `<div class="article-body__inner">`（公告列表页为 `<ul class="card-list__body">`）；页头/页脚/nav 在容器外。
- **动态区块**：图片 URL 带 `auth_key` 时效参数、`?ver=` 资源版本、yoast schema（head）——提取时剥 `<img>/<script>/<style>` 与全部标签属性，只留 (标签, 纯文本) 序列，避免假阳性。
- 赛制页 `/tcg-rules-regulation`：`<h3 class="line-block__title">` 分节（标准/开放）；`更新日期：2026年7月16日`、`（自2026年7月16日起）`；标准赛制标记句"赛制标记为 G、H、I 的卡牌和8种基本能量卡"；白名单/旧卡为 `<li class="list-dote">`；开放赛制禁卡在"以下卡牌无法加入卡组中"之后的 li。
- **"特别的卡牌"外链 = `/tcg-rules-regulation-extra/`**，实测是 GX/棱镜之星/究极异兽/TAG TEAM/V-UNION 等**特殊机制说明页**（非 PRD 推测的"视作覆盖清单"）——无结构化字段可解析，只做 hash 监控 + 变更时生成 needs_manual 提案。此实测偏差需回写 PRD 2.1 注记。
- 公告列表页 `/category/tcg`：`<li class="card__element">` → a[href] + `.card__products-title` + `time.card__footer--category` + `time.card__footer--date`；只含第一页（新公告在顶部，够用）。

## 设计
- `ptcgdb/monitor/l1.py`：
  - `extract_main_text(html, kind)`：stdlib HTMLParser，容器内逐块 (tag, text) 规范化序列（kind=regulation/extra/news）
  - `content_hash(text)`：sha256
  - 快照存储 `data/monitor/l1/{page_id}.json`（hash + fetched_at + excerpt + 公告条目；data/ gitignored）
  - `parse_regulation(text)`：两赛制 effective_from / allowed_marks / 白名单 / 特典 / 禁卡 + `parse_errors`（关键句缺失即记录，不猜）
  - `build_proposal(...)`：**SnapshotSeed 超集**（顶层即 SnapshotSeed 字段，另加 proposal_id/detected_at/status/diff/parse_errors/raw_excerpt；Pydantic extra=ignore，`apply_snapshot` 可直接消费）。解析失败时快照字段沿用当前值 + `status: needs_manual`
  - `run_l1(fetcher, db_path, store_dir, proposals_dir, *, baseline=False, on_event=None)`
- CLI `ptcgdb monitor l1 [--baseline]`：httpx 串行抓取，间隔 ≥2s，仅 3 次请求
- 契约测试用真实页面 fixture（`tests/fixtures/l1/`，recon 保存的 HTML）

## 完成总结（DONE 时填写）

2026-08-01 完成，实测与结论：

- **产物**：`ptcgdb/monitor/l1.py`（提取/解析/存储/提案/run_l1 全链路）；CLI `ptcgdb monitor l1 [--baseline]`；`tests/test_l1.py` 10 个测试；真实页面契约 fixture `tests/fixtures/l1/`（regulation/extra/news 三页 HTML，2026-08-01 recon）。
- **提案 = SnapshotSeed 超集**：顶层即 SnapshotSeed 字段 + proposal_id/detected_at/status/diff/parse_errors/raw_excerpt（Pydantic extra=ignore），`apply_snapshot` 直接消费——端到端测试验证：轮换变更（G,H,I→H,I,J + 生效日 2026-09-16）→ 提案 → apply → 新快照 `standard-2026-09-16` 生效、旧快照闭合保留。
- **不猜测原则落实**：赛制标记句缺失 → `status: needs_manual` + `parse_errors`，allowed_marks 沿用当前快照；开放赛制"三个系列"口径不可机械映射标记字母，白名单能量种类同样沿用快照并在文档注明；extra/news 页变更只生成 needs_manual 提案。
- **noop 语义**：hash 变但解析内容与当前快照一致（注释文字微调）→ 不出提案，store 照更新，不误报。
- **真实运行验证（2026-08-01）**：三页基线建立（`data/monitor/l1/`，各 1 次请求、限速 2s）；紧接第二轮全部 unchanged——生产环境剔除 auth_key/页脚/ver 等动态区块有效，零假阳性。
- **解析器实现要点（踩坑记录）**：①img/br 等 void 元素无结束标签，不能入深度栈（否则后续数据全被吞）；②块标签可嵌套（开放赛制特典 li 套在 p 内），新块开始须先闭合当前块；③禁卡区以 h3/h4 分节为结束（"关于过去系列的卡牌"在禁卡列表之后）。
- **PRD 回写**：§2.1 "特别的卡牌"外链实测为特殊机制说明页（非 v1.3 推测的视作覆盖清单），修订记录 v1.4（续，task 014）。
- 测试基线：138 全绿（128 + 新增 10），ruff 全净。
