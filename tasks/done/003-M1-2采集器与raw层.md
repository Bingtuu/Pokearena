## 目标

实现主数据源采集器：`product-list → product-detail → card-detail` 三级链路，原始响应 append-only 落 raw 层，含限速/重试/熔断/断点续传/三清单日志。**小样本验证**（1~2 个系列），全量抓取在 task 005 执行。

## 硬性约束（goal 限速红线）

- ≤1 次/2 秒（注入式限速器，测试时为 0）；连续出错自动降速到 5 秒/请求
- 指数退避最多重试 3 次
- 连续 5 次失败、或出现 HTTP 403 / 非 JSON 响应（疑似验证码/封禁页）→ 立即中止本轮运行并输出告警，不硬闯
- 诚实 User-Agent（标明非商业研究用途）；不请求 CDN 卡图

## 步骤

- [x] `scrapers/http.py`：RateLimiter（注入式 clock/sleep，默认 2s，出错降速 5s）+ HttpClient（httpx + tenacity 退避 3 次 + 熔断器 CircuitOpenError）
- [x] `scrapers/mikmoe.py`：三端点封装；cardIndex 强制字符串（传整数本地 TypeError）；响应校验 code==200 且 data 非空否则 MikMoeApiError
- [x] raw 层落盘：products.json / {setId}/cards.json / {setId}/{cardIndex}.json；内嵌 `_meta`（fetched_at / source / content_hash=sha256）；append-only = 存在且 hash 有效即跳过，--force 重抓
- [x] 断点续传：card 级粒度，raw 存在即跳过；`--force` 强制重抓
- [x] 三清单日志：scraped/question/missing → `data/raw/runs/{run_id}/` + scrape_runs 落库（counts/lists_path/manifest_hash/status）
- [x] CLI：`ptcgdb scrape sets`、`ptcgdb scrape cards [--set SET_ID] [--force]`
- [x] 测试：16 个测试全 MockTransport 零网络（限速/退避/熔断×3 场景/响应校验/raw 跳过与 force/三清单落库/resume）
- [x] 小样本实测：CSM1aC 全 211 张（真实网络，7 分 03 秒，≈2.0s/请求）

## 完成总结

**做了什么**：采集层全链路落地——注入式限速 HTTP 层（2s/请求、出错降速、退避、三路熔断）、mik.moe 三端点封装、append-only raw 层（sha256 manifest）、card 级断点续传、三清单日志 + scrape_runs 落库、CLI 两个子命令。真实网络小样本（CSM1aC 211 张）一次跑通，resume 重跑 1 秒内完成零请求。

**发现的字段形态偏差（已修复 + 文档同步）**：product-list 的 `data` 是 `{"list": [...]}` 包装而非裸数组——docs/mikmoe-api.md 已更新，runner 兼容两种形态。首跑曾因该偏差解析崩溃，但 append-only 设计使已落盘产物无损复用，未造成数据污染（崩溃轮未写 scrape_runs，行为正确）。

**顺带修复**：`python -m ptcgdb.cli` 缺 `__main__` 守卫空转退出，已补。

**与预估的偏差**：无（约半天，含 7 分钟实测）。
