## 目标

验证官方小程序"宝可梦卡牌会员"接口的可行性，完成 D1 决策：

- **路线 A**：主源 = 小程序接口（数据一手、结构化 JSON、字段最全）
- **路线 B**：主源 = tcg.mik.moe 镜像（公开网页、同源二手数据、零合规风险）

无论选哪条，两条 scraper 最终都要写（PRD 双源交叉校验），本任务只决定**谁主谁辅**。

### 3. 可行性判定（~2h）

- [x] **礼貌探测**：未执行（加密层已判负，无需打扰对方服务器）

### 5. 输出 D1 决策（~1h）

## D1 决策矩阵

| 情况 | 决策 |
|---|---|
| 重放成功、无签名或签名可还原、无频控 | A（小程序为主源，mik.moe 为校验源） |
| 有签名但 30 分钟内可还原 | A，但在风险登记册上调风控概率 |
| 签名无法还原 / 需登录态+设备指纹 / 触发风控 | **B（mik.moe 为主源），M1 预算 +1~2 天** ← 实际命中 |
| 两条都走不通（极端情况） | 升级上报，重新评估数据源策略，不进 M1 |

## 完成总结

**做了什么**：搭建 mitmproxy 抓包环境（脚本化：证书/系统代理/录制全自动，用户仅操作小程序）；抓包定位官方小程序 API（app-api.pokemon-tcg.cn）；判定路线 A 不可行；转向验证 tcg.mik.moe，从其前端 JS bundle 中发现 `/api/v3/card/*` 结构化 JSON API 并逐端点实测通过。

**D1 结论：路线 B（tcg.mik.moe 为主源）**。理由：① 官方小程序接口有 JWT 登录态 + 请求/响应 AES 加密 + 签名四层防护，还原需反编译 wxapkg，远超 M0 标准；② mik.moe API 无鉴权、明文 JSON、字段完整（含赛制标记、进化、能量成本、特性/招式、双对账字段 cardsNum、regulationLegal 交叉校验位、effectId 同效果归组、英文映射——多个字段超出预期，直接利好 name_group 与 Phase 2 映射）。

**意外收获**：mik.moe 的 `effectId`/`effectSameCards`/`regulationLegal`/`setCodeEn+cardIndexEn+nameEn` 字段可为 name_group 归组、合法性交叉校验、Phase 2 英文映射提供现成参考。

**与预估的偏差**：无（约半天完成，timebox 内）。

**遗留问题**：① mik.moe 能量/属性单字母编码与【】占位符的完整映射表需 M1 用黄金样本核证（特别是 Y/N 码与龙/无的对应）；② 训练家宝可梦、V-UNION、太晶、mechanic/label 字段取值需 M1 多样本确认；③ 小程序接口若未来去掉加密，可重开 D1 评估（届时已有双 scraper 架构，切换成本低）。
