## 目标
把 M1~M3 沉淀的能力变成**可一键重跑的正式验收**：A1 白名单逐卡核对器（新代码）+ 验收 runner 重跑 A1/A4/A5/A6/A7/A8 并产出证据报告。

## 设计
- `ptcgdb/legal/audit.py`（A1）：`audit_format(session, fmt, d)`——
  - 白名单逐条：name_full 能解析到归组（诊断）且 `legal_at` 的 `by_name_group` 有合法印刷（判定）
  - 能量双向：allowed 每种基本能量有合法卡；**反向**：词表内不在 allowed 的种类（如 standard 的妖）在池外
  - 返回 `AuditResult(entries, passed)`，不符项带原因，不猜测性修数据
- `ptcgdb/accept/runner.py`：`run_acceptance(db_path, out_dir, work_dir)` 依次跑——
  - A1：audit 两赛制（基于真实库，只读）
  - A4：两赛制 `legal_at(today)` 构建卡池 + 妖能量二分 spot check（库内有妖能量卡时）；构造用例 ≥12 组以 pytest 全绿为证据（报告注明）
  - A5：副本库种子 → 提案 → `apply_snapshot` → 新快照生效/旧快照闭合可查询/冻结守卫拒绝写
  - A6：副本库脏合入（删行）→ `rollback` → 行数复原
  - A7：`export_all` 到临时目录 → 七件套存在 + `checksums.sha256` 逐一校验 + manifest 含双轨版本
  - A8：SDK `open_db`(真实库) vs `open_jsonl`(A7 导出) 对同一查询集（get/search/legal_at/effective_text）结果一致
  - 产出 `reports/acceptance-YYYYMMDD.md`（逐项 PASS/FAIL + 证据摘要）
- CLI `ptcgdb accept`
- 边界：真实库只读；A5/A6 全在 work_dir 副本；runner 任一项失败仍跑完其余项，报告如实记录
