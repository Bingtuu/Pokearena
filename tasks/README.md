# tasks/ — 任务工作循环（开发标准）

本目录是开发的唯一任务队列。**先写任务文档，再写代码**；完成任务后立即归档并同步状态文档。

## 文件组织

```
tasks/
├── README.md            # 本规范
├── NNN-任务名.md         # 进行中/待办的任务（平铺，一眼看到当前工作）
└── done/
    └── NNN-任务名.md     # 已完成任务（git mv 归档，保留历史）
```

- 编号 `NNN` 三位数顺序递增，**永不复用**（归档后也不补号）。
- 任务名用简短中文动宾结构，如 `002-建库schema与迁移脚本.md`。

## 任务文档模板

```markdown
# NNN · 任务名

| 项 | 内容 |
|---|---|
| 状态 | TODO / DOING / DONE |
| 关联 | PRD §章节、里程碑 Mx、验收标准 Ax |
| 预估 | x 天 |

## 目标
一句话说清要完成什么、为什么。

## 步骤
- [ ] 具体可执行的步骤

## 验收标准
- [ ] 可勾检的完成条件（尽量对应 PRD 第 10 章）

## 完成总结（DONE 时填写）
做了什么 / 验收结果 / 与预估的偏差 / 遗留问题
```

## 工作循环

1. **拆任务**：从 PRD 里程碑拆出任务，粒度 = 0.5~2 天可完成、有明确验收条件。写 `NNN-任务名.md`（状态 TODO）。
2. **开工**：状态改 DOING；`STATUS.md` 当前状态更新为"正在进行 NNN"。同一时刻原则上只有一个 DOING。
3. **完工**：
   - 逐条核对验收标准，全部通过；
   - 填写"完成总结"，状态改 DONE；
   - `git mv` 到 `tasks/done/`。
4. **同步**（完工的同一次提交内完成）：
   - `STATUS.md`：勾选对应里程碑项、更新当前状态、追加进展日志；若涉及决策，记决策日志；
   - 开发进度只进 `STATUS.md` / `AGENTS.md`，**不进 README.md**——README 是项目门面，不承载开发流程与进度。
5. **提交**：任务文档、代码、状态同步放同一 commit，信息前缀 `task(NNN):`。

## 原则

- 任务文档可以小，但不能没有——口头开工不允许。
- 验收标准过不了就不算 DONE，不"先记完成再补"。
- 做不完的任务不删，留 TODO 并注明阻塞原因。
- PRD 是设计权威：任务中发现设计要改，先改 PRD 再继续（AGENTS.md 工作方式）。
